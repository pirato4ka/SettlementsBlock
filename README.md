# БНС_ФК_Сборка — расширение БНС_АдаптацияКонфигурации с блоком финансового контроля

Собрано на базе вашей выгрузки `src/БНС_ФК_Эталон` (формат 2.20, платформа 8.3.27).
Родные объекты эталона не тронуты: только дописаны новые и расширен `Configuration.xml`
(+`ChildObjects`, без него платформа и падала с «ожидаемое ChildObjects»).

## Загрузка

1. Резервная копия базы (обязательно — грузится расширение целиком).
2. Конфигуратор → `Конфигурация` → `Расширения конфигурации` → выделить `БНС_АдаптацияКонфигурации`
   → `Конфигурация` → `Загрузить конфигурацию из файлов…` → папка `src/БНС_ФК_Сборка`.
3. `Обновить конфигурацию базы данных` (расширение, не основная).

## Ручные шаги, которые файлами не выгружаются

### 1. Подписки на события — уже в файлах

`EventSubscriptions/БНС_ПроверкаЛимитаПриПроведении.xml` и `EventSubscriptions/БНС_ЗащитаСтатусаФинансовогоКонтроля.xml`
(в `Configuration.xml` они прописаны, в `ConfigDumpInfo.xml` — тоже):

| Имя | Источник | Событие | Обработчик |
|---|---|---|---|
| `БНС_ПроверкаЛимитаПриПроведении` | `Документ.ЗаказКлиента` | `Posting` (ОбработкаПроведения) | `CommonModule.БНС_Подписки.ПроверкаЛимитаПриПроведении` |
| `БНС_ЗащитаСтатусаФинансовогоКонтроля` | `Документ.ЗаказКлиента` | `BeforeWrite` (ПередЗаписью) | `CommonModule.БНС_Подписки.ЗащитаСтатуса` |

Для `РеализацияТоваровУслуг` — сначала заимствовать документ в расширение
(`Правой кнопкой → Добавить в расширение`), добавить ему те же 9 реквизитов `БНС_*`,
что уже есть у `ЗаказКлиента`, затем в оба файла подписок добавить второй источник:
`<v8:Type>cfg:DocumentObject.РеализацияТоваровУслуг</v8:Type>`.

### 2. Включение

`Константа.БНС_ИспользоватьФинансовыйКонтроль = Истина`, заполнить правила и их значения.
Первый месяц — режим `Предупредить`, потом точечно `Запретить`.

### 3. Кнопки контролера

Стандарт оповещений — как в вашем коде:

| Слой | Механизм | Где |
|---|---|---|
| Сообщения при проведении (сервер) | `ОбщегоНазначения.СообщитьПользователю(...)` | `БНС_ОбщегоНазначения.ВывестиСообщение` |
| Тост-оповещения (клиент) | `ПоказатьОповещениеПользователя(...)` | `БНС_ОповещенияКлиент` |

Тост из подписки на проведение невозможен — это клиентский метод. Поэтому причины отказа
идут в панель сообщений через БСП, а тосты — из команд и форм:

```bsl
// кнопка формы документа
БНС_ОповещенияКлиент.РазрешитьОтгрузку(Объект.Ссылка, "Согласовано финдиректором");
БНС_ОповещенияКлиент.ЗапретитьОтгрузку(Объект.Ссылка, "Просрочка более 60 дней");
```

Каждая из них ставит статус, проводит документ и показывает тост; при ошибке —
тост `ОповеститьОбОшибке` с `КраткоеПредставлениеОшибки`.

Серверный аналог для сценариев без формы —
`БНС_Подписки.УстановитьСтатусКонтроля(ДокументСсылка, НовыйСтатус, Комментарий)`.

### 4. Вывод статуса на форму — программно

Разметка формы не правится: элемент создаётся кодом в расширенном модуле формы
`Документ.ЗаказКлиента.Форма.ФормаДокумента`, обработчик `БНС_ПриСозданииНаСервереПосле`
(зарегистрирован в форме как `OnCreateAtServer` с `callType="After"`):

```bsl
Если Элементы.Найти("БНС_СтатусФинансовогоКонтроля") = Неопределено Тогда
	ПолеФинансовогоКонтроля = ЭтаФорма.Элементы.Добавить("БНС_СтатусФинансовогоКонтроля", Тип("ПолеФормы"), Элементы.ГруппаСтатусПриоритет);
	ПолеФинансовогоКонтроля.Вид = ВидПоляФормы.ПолеВвода;
	ПолеФинансовогоКонтроля.Заголовок = "Финансовый контроль";
	ПолеФинансовогоКонтроля.ПутьКДанным = "Объект.БНС_СтатусФинансовогоКонтроля";
	ПолеФинансовогоКонтроля.ТолькоПросмотр = Истина;
	ПолеФинансовогоКонтроля.РастягиватьПоГоризонтали = Ложь;
	ПолеФинансовогоКонтроля.Ширина = 16;
КонецЕсли;
```

Поле появляется в шапке рядом со «Статус» / «Приоритет». В конструкторе формы его не видно —
оно существует только во время выполнения. Остальные реквизиты (`БНС_ДолгНаМоментПроверки`,
`БНС_ПревышениеСуммы` и т.д.) на форму не выводятся: они видны в сообщениях, отчёте и регистре истории.

### 5. Поля на карточке партнёра — программно

Файл `Catalogs\Партнеры\Forms\ФормаЭлемента\Ext\Form\Module.bsl` содержит обработчик
`БНС_ПриСозданииНаСервереПосле`, который добавляет в карточку партнёра:

| Поле | Заголовок | Доступ |
|---|---|---|
| `БНС_КаналПродаж` | Канал продаж | ввод |
| `БНС_ГруппаКлиентов` | Группа клиентов | ввод |
| `БНС_ПарныйПартнер` | Парный профиль | только просмотр |
| `БНС_Ответственный` | Ответственный | только просмотр |

Группа для размещения ищется по именам `ГруппаДополнительно` → `ГруппаПрочаяИнформация` →
`ГруппаОбщаяИнформация`; если ни одной не найдено — поля добавляются в корень формы.
Разметка при этом не правится.

Чтобы обработчик заработал, форма должна быть заимствована, и событие зарегистрировано.
В `Catalogs\Партнеры\Forms\ФормаЭлемента\Ext\Form.xml` в блок `<Events>` добавить строку:

```xml
<Event name="OnCreateAtServer" callType="After">БНС_ПриСозданииНаСервереПосле</Event>
```

Порядок включения:

1. Конфигуратор → `Справочники → Партнеры` → правой кнопкой → «Добавить в расширение».
2. `Партнеры → Формы → ФормаЭлемента` → «Добавить в расширение».
3. Выгрузить расширение в файлы (или отдать мне — допишу событие и `ConfigDumpInfo`).
4. Обновить конфигурацию БД, открыть партнёра — четыре поля появятся на карточке.

До заимствования формы поля можно заполнить через «Ещё → Изменить форму» в карточке партнёра:
это пользовательская настройка, конфигурацию не меняет.

## Два профиля клиента — как завести

|
Шаг | Что сделать
--- | ---
1 | `БНС_ГруппыКлиентов` → «ООО Ромашка», ИНН для сверки дублей. `БНС_Ответственный` подставится сам
2 | `Партнеры` → «ООО Ромашка (Легальный)»: `БНС_КаналПродаж` = Легальный, `БНС_ГруппаКлиентов` = ООО Ромашка
3 | `Контрагенты` → «Ромашка» с ИНН и КПП, реквизит `Партнер` = ООО Ромашка (Легальный)
4 | `Партнеры` → «ООО Ромашка (контур 2)»: `БНС_КаналПродаж` = Теневой, та же группа
5 | `Контрагенты` → «Ромашка (контур 2)»: **ИНН пустой**, реквизит `Партнер` = ООО Ромашка (контур 2)

Ключевое: у контрагента есть реквизит `Партнер`, то есть **контрагент принадлежит одному партнёру**.
Одного контрагента на два профиля повесить нельзя. Второму профилю нужен свой контрагент,
и ИНН у него лучше не заполнять — иначе в базе два юрлица с одинаковым ИНН и типовые отчёты начнут их путать.

## Что сверить в базе (в коде помечено FILL)

1. `РегистрНакопления.РасчетыСПокупателями` — имя измерения `Партнер` и ресурса
   остатка (`СуммаРасчетовОстаток`) в `БНС_КонтрольЛимитовСервер.ЗадолженностьНаДату`.
2. `ОтсрочкаПоДоговору()` — сейчас возвращает 0; подставить реквизит договора со сроком оплаты.
3. `КонтрагентПартнера()` — ищет контрагента по реквизиту `Контрагенты.Партнер` (у контрагента один партнёр), обёрнуто в `Попытка`.
4. `РегистрСведений.КурсыВалют` — пересчет валюты лимита, тоже в `Попытка`.

## Логика контроля (коротко)

- Правило ищется на **дату документа** (не на текущую), приоритет: Партнер → Контрагент → Группа;
  организация в отборе не участвует (в базе одна организация); закрытый интервал `ДействуетПо` не применяется.
- Долг считается на `КонецДня(Дата документа)` по `РасчетыСПокупателями`, сам проверяемый документ исключается,
  отрицательные остатки (авансы) не учитываются.
- Проверяется **прогнозный** долг: `долг + сумма документа`.
- Просрочка — по каждой непогашенной накладной (остаток в разрезе регистратора), в расшифровку
  попадают конкретные документы с суммой и числом дней.
- Нарушение при `Запретить` ставит `Отказ = Истина`; при `Предупредить` документ проводится
  со статусом `НаПроверке`. Статус `ОтгрузкаРазрешена` снимает проверки полностью,
  `ОтгрузкаЗапрещена` блокирует проведение для всех.
- При изменении суммы / партнёра / даты разрешение сбрасывается (подписка `ПередЗаписью`).
