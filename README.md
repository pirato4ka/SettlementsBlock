# БНС_АдаптацияКонфигурации: блок контроля дебиторской задолженности

Расширение для **Управление торговлей 11.5.26.118** (платформа 8.3.27).
Реализует требования `task.txt`: исторические лимиты взаиморасчетов, проверку
задолженности при проведении отгрузки, ручное решение контролера, расшифровку
причины отказа, роли и отчёт.

## Состав расширения

| Объект | Назначение |
|---|---|
| `Catalog.БНС_ЛимитыВзаиморасчетов` | Правило контроля: объект контроля (партнёр/контрагент), организация, лимит, валюта, допустимая просрочка, действие при нарушении, период действия, комментарий |
| `Catalog.БНС_ЛимитыВзаиморасчетов.Ext.ObjectModule` | `ПриЗаписи` пишет версию настроек в регистр `БНС_ЗначенияЛимитов` |
| `InformationRegister.БНС_ЗначенияЛимитов` | Периодический (день) регистр версий настроек: измерение `Лимит`, ресурсы-снимок всех параметров и автор изменения |
| `InformationRegister.БНС_ИсторияФинансовогоКонтроля` | Снимки проверок: документ, статус, применённый лимит, долг, превышение, просроченная накладная, пользователь |
| `Enum.БНС_СтатусыФинансовогоКонтроля` | `Пусто`, `НаПроверке`, `ОтгрузкаРазрешена`, `ОтгрузкаЗапрещена` |
| `Enum.БНС_ДействияПриНарушении` | `Запретить` (жёсткий режим), `Предупредить` (мягкий режим) |
| `Constant` + `FunctionalOption.БНС_ФинансовыйКонтроль` | Включение подсистемы |
| `CommonModule.БНС_КонтрольЛимитовСервер` | Выбор версии лимита, расчёт долга и просрочки, текст расшифровки |
| `CommonModule.БНС_Подписки` | Обработчики подписок и серверный API решения контролера |
| `CommonModule.БНС_ОбщегоНазначения` | Флаг подсистемы, сообщения, журнал, права, запись истории |
| `CommonModule.БНС_ИсторияФинансовогоКонтроляСервер` | Привилегированная запись истории (роль просмотра не получает право изменения регистра) |
| `CommonModule.БНС_ОповещенияКлиент` | Тост-оповещения пользователя |
| `Report.БНС_РасшифровкаФинансовогоКонтроля` | Отчёт по истории: статус → документ, лимит, долг, сумма документа, превышение, просрочка |
| `Role.БНС_ФинансовыйКонтроль_Просмотр` / `..._Изменение` | Просмотр и ведение настроек |
| `Subsystem.БНС_ФинансовыйКонтроль` | Командный интерфейс подсистемы |
| Подписки `БНС_ПроверкаЛимитаПриПроведении`, `БНС_ЗащитаСтатусаФинансовогоКонтроля` | Проверка при проведении и защита статуса при записи для `ЗаказКлиента` и `РеализацияТоваровУслуг` |
| 9 реквизитов `БНС_*` в `ЗаказКлиента` и `РеализацияТоваровУслуг` | Статус, снимок проверки, автор и дата решения, комментарий контролера |

## Загрузка

1. Резервная копия базы.
2. Конфигуратор → «Расширения конфигурации» → `БНС_АдаптацияКонфигурации` →
   «Загрузить конфигурацию из файлов» → каталог репозитория.
3. «Обновить конфигурацию базы данных».

`ConfigDumpInfo.xml` содержит служебные контрольные суммы выгрузки. Если конфигуратор
сообщит о несовпадении версий, выполните полную загрузку расширения из файлов
(не «обновить изменениями»): содержимое модулей и метаданных в файлах актуально.

## Настройка

1. `Константа.БНС_ИспользоватьФинансовыйКонтроль = Истина` (или функциональная опция
   в разделе «Администрирование»).
2. Профили: контролёру — роль `БНС_ФинансовыйКонтроль_Изменение`, менеджерам —
   `БНС_ФинансовыйКонтроль_Просмотр`.
3. Справочник «Лимиты взаиморасчетов»: создать правило и заполнить параметры.
   - `Объект контроля` — партнёр или контрагент.
   - `Организация` — пусто означает «все организации».
   - `Действие при нарушении` — начинать внедрение следует с `Предупредить`.
   - `Действует с` — дата начала действия версии настроек.
4. При каждой записи правила его настройки копируются в `БНС_ЗначенияЛимитов`.
   Чтобы сохранить историю, при следующем изменении укажите новую дату
   `Действует с`: предыдущая версия останется в регистре и будет применяться
   к документам, проведённым задним числом.
5. Для снятия правила снимите флаг `Активна` и запишите элемент — версия с этим
   периодом прекращает действие правила. Удаление элемента также исключает правило
   из контроля.

## Как работает контроль

**При проведении** (`ОбработкаПроведения`, подписка):

1. Если подсистема выключена, документ загружается обменом или помечен на удаление —
   проверки нет.
2. Статус `ОтгрузкаЗапрещена` — отказ с текстом решения контролера.
   Статус `ОтгрузкаРазрешена` — проведение без проверки.
3. Подбирается версия лимита: срез `БНС_ЗначенияЛимитов` на конец дня документа,
   только активные версии, правила удалённых элементов игнорируются. Приоритет:
   партнёр важнее контрагента, конкретная организация важнее «все организации».
4. Считается долг на дату документа по регистру `РасчетыСПокупателями`:
   суммируются остатки по партнёру (для правила на контрагента — по этому
   контрагенту), при необходимости — по организации правила; отрицательное
   сальдо уменьшает долг, итог не может быть отрицательным. Движения самого
   проверяемого документа из долга вычитаются: подписка вызывается после
   обработчика проведения, когда движения уже записаны, иначе сумма документа
   учитывалась бы дважды.
5. Прогнозный долг = долг + `СуммаДокумента`. Нарушение по сумме — превышение
   лимита; нарушение по сроку — просрочка больше допустимой. Просрочка считается
   от срока оплаты накладной (дата отгрузки + отсрочка по договору).
6. `Предупредить` — документ проводится со статусом `НаПроверке` и сообщением.
   `Запретить` — `Отказ = Истина`, сообщение с расшифровкой и запись в журнал
   регистрации `БНС.ФинансовыйКонтроль.Отказ`.
7. Сбой проверки блокирует проведение (fail-closed) и пишется в журнал
   `БНС.ФинансовыйКонтроль.Сбой`.

**При обычной записи** документ не блокируется, но статус и снимок проверки
заполняются. Благодаря этому непроведённый документ с превышением виден в отчёте
и контролёру не нужно ждать попытки проведения.

**Сообщение при отказе** содержит применённое правило и дату версии, долг, сумму
документа, прогнозный долг и лимит, сумму превышения, а также перечень просроченных
накладных с датой, суммой и количеством дней просрочки.

## Решение контролера

Кнопки «Разрешить отгрузку» и «Запретить отгрузку» создаются программно в модулях
форм `ЗаказКлиента` и `РеализацияТоваровУслуг` (макет формы не правится) и видны
только пользователям с ролью `БНС_ФинансовыйКонтроль_Изменение`.

Порядок: документ должен быть сохранён (иначе выводится предупреждение) →
`БНС_Подписки.ПринятьРешение` записывает статус, автора, дату и комментарий
отдельной транзакцией → пишется история → для «Разрешить» выполняется проведение.

- Запрет остаётся в документе даже при неудачном проведении и блокирует следующие
  попытки до нового решения.
- Разрешение сохраняется и отменяет проверку лимита при проведении.
- Изменение суммы, партнёра, контрагента или даты сбрасывает разрешение и
  возвращает статус `НаПроверке`.
- Поля «Разрешил отгрузку» и «Дата решения» недоступны для ручного изменения.

Серверный аналог для внешних обработок:
`БНС_Подписки.ПринятьРешение(ДокументСсылка, НовыйСтатус, Комментарий)` —
возвращает структуру `Успех`, `ТекстОшибки`, `ТекстСообщения`, `Статус`.

## Элементы форм — только программно

Поле «Финансовый контроль», поле комментария контролера, кнопки решения и команда
перезаполнения МРЦ добавляются в `БНС_ПриСозданииНаСервереПосле`. Событие
`OnCreateAtServer` с `callType="After"` зарегистрировано в `Form.xml` расширения.
Создание идемпотентно: повторный вызов не дублирует команды и элементы.
Если типовая форма не содержит ожидаемых групп (`ГруппаСтатусПриоритет`,
`ГруппаОсновныеДанные`, `ФормаКоманднаяПанель`), элементы добавляются в корень формы.

## Границы и адаптация под конкретную базу УТ

В среде разработки нет платформы 1С, поэтому модули не компилировались и запросы
не выполнялись на живой базе. Перед промышленным включением проверьте:

- имена в регистре `РасчетыСПокупателями`: модуль сам определяет ресурс остатка
  (`СуммаРасчетов` / `Сумма` / `СуммаДолга` / единственный ресурс) и измерение
  документа расчетов (`ДокументРасчетовСКонтрагентом` / `ДокументРасчетов` /
  `Документ`); если ресурс не найден, контроль завершается отказом с явным текстом;
- наличие реквизита `Договор` у документов расчетов и реквизита отсрочки
  (`ОтсрочкаОплаты`, `ОтсрочкаОплатыДней`, `СрокОплатыДней`, `ОтсрочкаДней`)
  у договора: при отсутствии отсрочка считается нулевой, и просрочка отсчитывается
  от даты накладной;
- курсы валют: если курс не найден, сумма сравнивается как есть (без пересчёта),
  чтобы отсутствие курса не блокировало отгрузки;
- нулевой лимит по сумме трактуется как «контроль по сумме не задан»;
- при вычитании движений проверяемого документа используется отбор по тем же
  измерениям (партнёр/контрагент/организация), поэтому документ, записавший
  движения по другому партнёру, будет учтён один раз — как сумма документа;
- справочник `БНС_ГруппыКлиентов` оставлен как вспомогательный объект ранней версии
  и в алгоритме контроля не участвует: по `task.txt` контроль ведётся по партнёру
  или контрагенту.

## Автотесты

```
python -m unittest discover -s tests -v
```

Проверяются: корректность XML, BOM/CRLF, баланс блоков BSL, состав метаданных,
наличие обработчиков подписок и событий форм, отсутствие вызовов серверных модулей
из клиентского кода, fail-closed и тексты расшифровки, запрос отчёта.
