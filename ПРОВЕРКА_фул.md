# Приёмочный чек-лист расширения финансового контроля

Короткий маршрут проверки соответствия `task.txt`. Подробный сценарий — в
`ТЕСТ_полный_цикл.md`.

## A. Соответствие требованиям

- [ ] Справочник «Лимиты взаиморасчетов» позволяет задать объект контроля
      (партнёр/контрагент), организацию, лимит, допустимую просрочку, действие при
      нарушении, период действия и комментарий.
- [ ] История настроек ведётся в периодическом регистре: документ, проведённый задним
      числом, проверяется по версии, действовавшей на его дату.
- [ ] Отгрузочные документы (`ЗаказКлиента`, `РеализацияТоваровУслуг`) получают статус
      «На проверке» при превышении лимита и остаются пустыми при отсутствии превышений.
- [ ] Жёсткий режим не даёт провести документ, мягкий — только предупреждает.
- [ ] Контролер может установить «Разрешить отгрузку» (документ проводится без проверки)
      и «Запретить отгрузку».
- [ ] Сообщение при проведении содержит конкретную просроченную накладную и сумму
      превышения лимита, а не общее «контроль не пройден».
- [ ] Созданы две роли — просмотр и изменение; функционал собран в отдельную подсистему
      с константой (функциональной опцией) включения.
- [ ] Элементы форм добавляются программно, макет типовой формы не правится.

## B. Загрузка и метаданные (10 минут)

- [ ] Конфигуратор → Расширения → `БНС_АдаптацияКонфигурации` → «Загрузить конфигурацию из файлов».
- [ ] Ошибок нет; при сообщении о версиях выгрузки выполнить полную загрузку.
- [ ] Обновить конфигурацию базы данных.
- [ ] В расширении видны: 2 справочника, 2 регистра сведений, 3 перечисления, константа,
      функциональная опция, подсистема, 5 общих модулей, 2 подписки, 2 роли, отчёт,
      9 реквизитов в каждом из двух документов.
- [ ] У `БНС_ЛимитыВзаиморасчетов` заполнены 10 реквизитов правила; тип `ОбъектКонтроля` —
      партнёр и контрагент; `Организация` — справочник организаций.
- [ ] В `БНС_ЗначенияЛимитов` измерение одно — `Лимит`; среди ресурсов есть `Организация`,
      `ОбъектКонтроля`, `Активна`; периодичность — день.
- [ ] `БНС_ИсторияФинансовогоКонтроля` — периодичность до секунды, запись только через
      привилегированный модуль; обе роли имеют лишь `Read`/`View`.

## C. Включение (5 минут)

- [ ] `БНС_ИспользоватьФинансовыйКонтроль = Истина`.
- [ ] Подписки `БНС_ПроверкаЛимитаПриПроведении` (`Posting`) и
      `БНС_ЗащитаСтатусаФинансовогоКонтроля` (`BeforeWrite`) активны.
- [ ] Роли включены в профили: контролёру — `..._Изменение`, менеджерам — `..._Просмотр`.

## D. Данные (10 минут)

- [ ] Партнёр и контрагент созданы, у документа заполнены `Партнер`, `Контрагент`, `Организация`.
- [ ] Правило на партнёра, `Активна = Истина`, `ДействиеПриНарушении = Предупредить`,
      лимит 1 000 000, просрочка 90, `ДействуетС` = 01.11.2026.
- [ ] После записи правила в `БНС_ЗначенияЛимитов` появилась версия с периодом 01.11.2026.
- [ ] Долг: проведённая неоплаченная реализация от 01.09.2026 на 400 000.
- [ ] Заказ клиента на 700 000 от 02.11.2026 при записи получает статус «На проверке».

## E. Решения контролера (10 минут)

- [ ] Под ролью `..._Просмотр` кнопки решения не видны, поле статуса только для просмотра.
- [ ] Под ролью `..._Изменение` кнопка «Разрешить отгрузку» проводит документ:
      статус «Отгрузка разрешена», заполнены автор и дата решения.
- [ ] Кнопка «Запретить отгрузку» блокирует проведение; запрет сохраняется в документе
      после неудачной попытки проведения.
- [ ] Изменение суммы или даты разрешённого документа сбрасывает разрешение.

## F. Жёсткий режим и расшифровка (10 минут)

- [ ] Правило переведено в `Запретить` (новая дата `Действует с`).
- [ ] Документ не проводится; сообщение содержит номер и дату накладной, сумму долга,
      превышение и лимит.
- [ ] В журнале регистрации есть событие `БНС.ФинансовыйКонтроль.Отказ`.
- [ ] При имитации сбоя запроса — событие `БНС.ФинансовыйКонтроль.Сбой` и запрет проведения.

## G. Отчёт (10 минут)

- [ ] `БНС_РасшифровкаФинансовогоКонтроля`: группировка «Статус → Документ», колонки
      лимит/долг/сумма документа/превышение/просрочка/просроченная накладная.
- [ ] Пустой период показывает данные, заполненный — фильтрует.
- [ ] Флаг «Только нарушения» меняет состав строк.
- [ ] `БНС_ИсторияФинансовогоКонтроля` содержит записи с документом, статусом,
      пользователем, датой и комментарием.

## H. Диагностика и границы (10 минут)

- [ ] Проведение через обмен / документ с пометкой удаления — проверка не срабатывает.
- [ ] Аванс покупателя уменьшает долг, превышения нет.
- [ ] Разные организации: специфичное правило применяется к своей организации,
      общее — ко всем остальным.
- [ ] Правило на контрагента применяется к документам этого контрагента.

## I. Приёмка

- [ ] Этапы B–H пройдены без ошибок.
- [ ] Ни один сценарий не потребовал ручной правки метаданных.
- [ ] `README.md` соответствует фактическому поведению.
- [ ] Пройдены автотесты: `python -m unittest discover -s tests -v`.

После приёмки — месяц в режиме `Предупредить`, разбор ложных срабатываний,
затем точечно `Запретить`.
